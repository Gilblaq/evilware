# EVILWARE — The Unholy Core 3 Release Roadmap

This document is the source-of-truth checklist for taking EVILWARE from its current development build to a public Windows release. A green CI build means the application compiled and its automated checks passed; it does not mean every workspace is complete or that the product is store-ready.

## Current baseline

- [x] Qt 6 / C++20 Windows x64 application builds in GitHub Actions.
- [x] Windows installer and portable ZIP are generated by CI.
- [x] Automated smoke test verifies that all 20 navigation entries map to 20 pages.
- [x] Core foundations exist for project creation, source editing, local terminals, basic network diagnostics, file browsing, Git commands and package installation handoff.
- [ ] Specialist workspaces are not all complete; each must be implemented and tested before being advertised as finished.

## Release milestones

### 1. Package and dependency management — in progress
- [x] Curated initial catalogue of developer and security tools.
- [x] Exact package IDs and publisher website links.
- [x] Replace detached install launch with tracked winget processes.
- [x] Check whether a package is installed before offering actions.
- [x] Confirm every install, update, reinstall and uninstall.
- [x] Show process success/failure and diagnostic output.
- [ ] Validate package IDs and behavior on supported Windows versions.
- [ ] Add safe workspace dependency detection and consent-based installation.
- [ ] Add dependency policies, cancellation, retries and clear restart guidance.

### 2. Core workspace completion
- [ ] Dashboard actions and recent projects.
- [ ] System Monitor process inspection and verified resource metrics.
- [ ] Build Apps templates, toolchain checks and build/run workflows.
- [ ] Code Studio usability, file handling and language support.
- [ ] Windows and WSL terminal reliability.
- [ ] Git Manager operations and error handling.
- [ ] Complete each specialist workspace before marking it production-ready.

### 3. Security, reliability and privacy
- [ ] Package source and publisher verification strategy.
- [ ] Least-privilege installation; never elevate silently.
- [ ] Explicit permission prompts and user cancellation.
- [ ] Safe handling of command arguments and external process output.
- [ ] Crash handling, logs, settings backup and recovery.
- [ ] Dependency/license inventory and third-party notices.
- [ ] Automated tests plus manual Windows 10/11 validation.

### 4. Product and release experience
- [ ] Finalize startup artwork using the user's supplied source images.
- [ ] Finalize product icon, installer metadata and versioning.
- [ ] First-run setup and clear supported-system requirements.
- [ ] Help, onboarding, troubleshooting and release notes.
- [ ] Accessibility and keyboard navigation review.

### 5. Distribution
- [ ] Create official EVILWARE website and product/download pages.
- [ ] Publish signed installer and portable package with checksums.
- [ ] Set up update delivery and release rollback process.
- [ ] Prepare privacy policy, terms, license and support contact.
- [ ] Review Microsoft Store submission requirements and decide whether to publish there.
- [ ] Prepare public launch announcement and support process.

## Release gate

Do not call a build a public release until CI passes, installer/portable artifacts are verified, the application has been manually tested on a clean supported Windows machine, package installation and removal have been validated, legal/privacy materials are published, and the release artifacts have a trustworthy signing and checksum process.
